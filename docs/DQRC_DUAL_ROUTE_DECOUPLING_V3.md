## Short answers

1. **Why did the serial architecture fail?** Structurally, not by mis-tuning. In `u -> M(m) -> A -> P(g,J)` every signal reaching the processor has already passed through the `m`-dependent memory, so `X_P` must depend on `m`. V3 measures this directly: perturbing `m` at fixed `(g,J)` moves the serial architecture's processor features by `max|dX_P| = 1.42e-01`, more than nine orders of magnitude above the `1e-10` numerical tolerance. One-way transfer suppresses `P -> M` back-action but cannot remove `M(m) -> P`.

2. **Are processor features invariant to `m` in the dual-route architecture?** Yes, **exactly**. `max|X_P(m+d) - X_P(m-d)| = 0.000e+00` (bit-identical, not merely within tolerance) for both `dual_route_current` and `parallel_fixed_taps`, and the processor Hamiltonian and input operators are bit-identical across `m`. This is architectural: with no `M -> P` channel the two modules are simulated as separate circuits, so no code path exists by which `m` could reach the processor. The test is falsifiable -- an injected hidden `m -> processor` dependency makes it fail (`max|dX_P/dm| = 1.79e-02`).

3. **Are memory features invariant to `(g,J)`?** Yes, exactly: `max|dX_M/dg| = max|dX_M/dJ| = 0.000e+00`, and the memory configuration is bit-identical across `(g,J)`.

4. **Does the processor retain substantial standalone instantaneous NL?** In SMOKE: standalone `NL_0 = +1.404`; embedded in Architecture B, `NL_0 = +1.216 +/- 0.059`, i.e. `eta_NL(0) = 0.866`; Architecture C reaches `1.741` (`eta = 1.240`, above 1 because the tap buffer gives the processor more input information than the single-tap standalone baseline); the serial architecture retains `eta = 0.000`. **Important honesty note:** for Architecture B the retention is high largely *by construction* -- the processor is reset every macro step and driven only by `u_t`, so it is nearly the standalone processor by definition. The non-tautological comparison is the serial architecture's `0.000`.

5. **Does the memory module retain substantial long-delay memory?** Yes. `M(X_M)` rises monotonically with retention: `m=0.3 -> 1.478`, `m=0.6 -> 2.677`, `m=0.9 -> 3.450`, with no ceiling contamination (max ceiling fraction 0.83) and a feature count that is constant at 36 across all `m` (confirming `m` changes dynamics, not the readout). At `m=1` the bank is a faithful delay line: rail correlations with the corresponding lagged input are `1.000`.

6. **Does weak coupling improve temporal nonlinear processing?** Not measurably in SMOKE, and it costs isolation immediately. Across `lambda in {0, 0.05, 0.2}`: `NL_0` moves `1.272 -> 1.354 -> 1.393` while `NL_temporal` stays slightly negative (`-0.144 -> -0.197 -> -0.205`), and the structural cross-sensitivity rises from an exact `0` to `1.65e-02` and `6.53e-02`. Processor-carried memory `M(X_P)` jumps from `0.297` to `1.114` at `lambda = 0.05` -- the coupling mostly re-imports memory into the processor, which is the very confound V2.2 identified. No optimal nonzero `lambda` is claimed; the SMOKE scan is far too small to support one.

7. **Does matched-resource performance improve?** **NOT EVALUABLE.** The matched-resource Pareto criterion (Gate K) is only evaluated under held-out confirmation, which was not run.

8. **Which gates pass, fail, or remain not evaluable?** 4 PASS (A structural isolation, B numerical validity, C nontrivial memory, D nontrivial instantaneous NL), 0 FAIL, 7 NOT EVALUABLE (E, F, G, H, I, J, K). See the table below.

9. **What is the strongest supported claim?** **Level 2** (reduced memory back-action). Level 3 (local fixed-delay control decoupling) is *not* claimed: although structural isolation is exact, SMOKE mode cannot support it, and the seed, neighborhood and matched-resource gates are unevaluated.

The value was legal; the normalisation was not. `decoupled_qrc/operator_bounds.py` implements the correct bound and validates against identity, product, SWAP and Haar-random reference cases.

## 3. A further defect found while building V3 (not in the supplied list)

While validating the processor, `NL_0` came back as **exactly** `0.0000` including its *raw* component -- impossible for a genuinely nonlinear processor. The cause: `ipc.generate_profiles` randomly subsamples targets when the enumeration exceeds `max_targets_per_degree`, and at the V2.2-scale settings (`max_delay=5, max_degree=3, cap=6`) **not one single-delay profile survived** -- every retained degree-2 and degree-3 target was a *cross-delay product*. The delay-resolved capacities `C_{d,tau}` therefore had no target to measure and were forced to exactly zero for want of a target, not for want of signal.

This affects the V2.2 headline "7 of 8 candidate-seed evaluations showed no instantaneous NL": that result is confounded with target coverage and should not be read as evidence of absent nonlinearity. Fixed additively by `always_include_single_delays` (default `False`, so no earlier result silently changes; V3 always passes `True`), with deterministic ordering and regression tests covering the pathological case, the determinism, and the unchanged default path.

## 4. Architectures implemented

All four are built from the **same** memory bank and the **same** processor, so an A-vs-B comparison isolates the architecture rather than a change of modules.

| id | name | routes |
|---|---|---|
| A | `serial` | `u -> M(m) --lambda_serial--> P(g,J)`, no direct route |
| B | `dual_route_current` | `u -> M(m)` and `u -> P(g,J)`, no `M->P` channel |
| C | `parallel_fixed_taps` | `u -> M(m)` and `(u_t..u_{t-L+1}) -> P(g,J)` |
| D | `dual_route_weak` | B plus `M --lambda--> P` |

**Memory bank** (`decoupled_qrc/memory_bank.py`): `L` rails, diagonal encoding `rho(u) = (I + s Z)/2` with `s = 2u-1`, and rail-to-rail routing by a **fractional SWAP**, `SWAP^m`. `m=1` is a perfect shift register, `m=0` transfers nothing, and intermediate `m` tunes retention. `m` is a physically implemented channel parameter; it does not change the delay horizon, target set, regularization, feature count (verified constant at 36) or number of observables.

**Processor** (`decoupled_qrc/nonlinear_processor.py`): `H_P(d;g,J) = H_0(g,J) + sum_k d_k V_k` with `H_0 = g sum_i X_i + J sum_i Z_i Z_{i+1}`, and `V_k` on qubit `k mod N_P` alternating `Z, X, ...`. Verified `||[V_0,H_0]|| = 6.4 != 0` and `||[V_k,V_l]|| = 4.0 != 0` for same-qubit `Z`/`X` pairs. `R` microsteps per macro timestep via exact matrix exponentials (no Trotter error); reset every macro step through `qc.reset` (CPTP), verified trace-1, Hermitian and positive semidefinite.

**`M -> P` channel**: `exp(-i lambda (Z_mem ⊗ X_proc))`, a genuine two-qubit unitary. At `lambda = 0` it is exactly the identity, so Architecture D reduces **bit-for-bit** to Architecture B (asserted in tests).

## 8. Conclusion: **Outcome G -- Inconclusive**

SMOKE mode validates software only. Structural isolation and both module implementations are exercised end to end, and the structural result is exact and falsifiable -- but no scientific claim follows from SMOKE.

**Unexecuted:** the DISCOVERY stage (Sobol/LHS parameter search, 3+ reservoir x 2+ input seeds, 49+ surrogates), the CONFIRMATION stage (5 x 3 held-out seeds, 199+ surrogates, hierarchical bootstrap), the preregistered neighborhood sweep, and the matched-resource Pareto criterion.

**Claim ladder**

| level | claim | status |
|---|---|---|
| 1 | directional information transfer | supported |
| 2 | reduced memory back-action | supported |
| 3 | local fixed-delay control decoupling | **not supported** (SMOKE only) |
| 4 | seed- and neighborhood-robust decoupling | not supported |
| 5 | matched-resource Pareto expansion | not supported |

**Highest supported level: 2.** The full V3 claim -- *"architectural separation produces independently addressable memory and instantaneous nonlinear feature modules and may expand the matched-resource performance frontier"* -- is **not** asserted: only its first half has structural evidence, and the frontier half has none.

**Main risk for DISCOVERY, visible already:** the `(g,J)` surface of `NL_0` is nearly flat (`1.404` to `1.425` across the grid). Exact structural isolation makes the *denominators* of `R_M`/`R_NL0` zero, but Gate G still needs `(g,J)` to actually *steer* instantaneous nonlinearity. If the surface stays flat at DISCOVERY scale, the honest outcome is **B** (isolation works, processor nonlinearity too weak or insufficiently steerable), whose recommended remedy is a richer noncommuting encoding and more within-timestep depth -- not more inter-timestep persistence.

## 10. Limitations

- Only SMOKE was executed: 2 reservoir x 1 input seed, `T=90`, `L=3` rails, `N_P=3`, 19 surrogates.
- 10 of the 23 requested figures were produced. The remaining 13 (seed-level confirmation forest plots, neighborhood pass/fail map, Pareto plot, derivative-stability comparison across seeds, order-delay heatmaps at confirmation resolution, and related) require the DISCOVERY/CONFIRMATION stages and are deliberately absent rather than fabricated.
- `eta_NL(0) = 0.866` for Architecture B is high substantially *by construction*, since the reset processor driven by `u_t` is nearly the standalone processor by definition. The informative comparison is the serial architecture's `0.000`.
- The `(g,J)` surface is nearly flat at SMOKE scale (see §8).
- `NL_temporal` for Architecture B is slightly negative, consistent with noise around zero: with no memory route into the processor, the dual-route processor is not expected to carry temporal nonlinearity, and temporal NL is explicitly treated as an end-to-end system capability rather than something the processor alone must supply.
- Architecture C's classical tap buffer is a real resource and is recorded in every comparison; it is labelled a hybrid/modular delayed QRC throughout.
