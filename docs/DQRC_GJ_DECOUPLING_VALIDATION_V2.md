## 1. Executive summary

This is a **FAST-mode smoke test of a new validation framework**, run once, at a single seed, over a coarse 3x3 discovery grid. It confirms that every new V2 scientific-utility module (order-delay IPC decomposition, capacity-ceiling diagnostic, fair feature-budget/residualization analysis, nested seed streams, dimensionless controls, reset ablation, timescale fitting, back-action measurement) executes end-to-end without error and produces self-consistent numbers.

It is **not** a confirmatory experiment. FULL mode (>=5 reservoir seeds x >=3 input seeds, 5-point derivative stencils, held-out confirmation, neighborhood robustness) was not run. The numbers below describe one exploratory pass and must not be read as an established result.

That said, the exploratory numbers obtained are uniformly unfavorable to the decoupling hypothesis at every point checked: the best point found in a 9-point (g,J) discovery grid has `R_NL_instant = 0.95` (need >2), a response angle of `3.7 degrees` (need 70-110), and an instantaneous-nonlinearity value of `0.045` (Gate F fails). This is consistent with — not proof of — the V1 finding recorded in project memory that "the promising R_NL~5.4 signal does not survive... processor absorbs memory's own role too."

## 2. Exact claim tested

Does tuning the processor controls `(g, J)` change the processor's **instantaneous** nonlinear capacity `NL_instant` substantially more than it changes the memory's linear capacity `M`, while tuning the memory control `m` (`epsilon_M`) does the reverse — i.e., is there a local region of control space where `M` and `NL_instant` respond to *different* controls (`R_memory > 2` AND `R_NL_instant > 2` AND response angle in `[70,110]` degrees)?

This is **not** a claim that the overall memory-nonlinearity tradeoff is broken, nor that the directional architecture fails globally. It is a narrow, local, control-level decoupling claim, evaluated pointwise.

## 3. Why V1 was inconclusive

`docs/DQRC_GJ_DECOUPLING_VALIDATION.md` mixed the `shift` and `protected_integrable` memory variants, scanned near a possible capacity ceiling (M approx 6.97-7.00), compared a 3-feature memory block against a 375-feature processor block without any budget-matched or residualized control, conflated temporal memory recall with instantaneous nonlinear transformation inside a single legacy `NL` number, used unnormalized derivatives across parameters with different natural scales, and ran only 2 seeds. Full list of 8 confounds in the original task specification (not reproduced here in full; see the spec preserved in this project's history).

## 4. Architecture and controls (unchanged)

Directional DQRC: memory register (`N_M=2`, includes its own input qubit) -> fresh-ancilla collision interface (`theta=0.2`, `phi=0.8`, `ap_kind='xy'`, fixed) -> EOC processor (`N_P=5`, mixed SYK2/SYK4, parameterized by `(g,J)`). No architecture change from V1/Phase 4-6. No IDQNN, sewing, or shadow readout in this notebook.

Control ranges used for dimensionless normalization (`p_tilde = (p-p_min)/(p_max-p_min)`):
- `m` (epsilon_M): `[0.1, 1.0]`
- `g`: `[0.05, 0.6]`
- `J`: `[0.05, 0.6]`

## 5. IPC definitions

`compute_ipc_decomposed` (new, `decoupled_qrc/ipc_decomposition.py`) classifies every significant IPC profile by `(degree, delays)`:
- `M_long` = sum of degree-1 (linear) capacities across all tested delays (legacy "memory capacity", unchanged definition).
- `NL_instant` = sum of capacities for degree>=2 profiles whose only delay is 0 (a genuinely instantaneous nonlinear transform of the current input/state, no temporal recall).
- `NL_temporal` = sum of capacities for degree>=2 profiles touching any delay>0 (nonlinear function of *past* inputs — this is temporal memory expressed through a nonlinear channel, not "processing" in the sense the decoupling claim cares about).
- `NL_legacy` = `NL_instant + NL_temporal` (reproduces the original V1 `NL` definition exactly, for continuity).

`compute_ipc()` (the original function) is **unchanged in output** — refactored into a thin wrapper around the same underlying `compute_ipc_detailed()` records, verified bit-identical via the existing `tests/test_ipc.py` (7/7 passing) plus new regression tests in `tests/test_ipc_decomposition.py`.

## 6. Capacity-ceiling audit

`diagnose_ceiling()` computes three independent ceiling estimates — target-count (`max_delay+1`), feature-rank (`numpy.linalg.matrix_rank` on centered train features), and sample-size (`n_train`) — and flags contamination when `M_long` exceeds 95% of the minimum of the three.

Standalone-processor reproduction point: `M_long=4.171`, ceiling estimate `M_max_effective=6.0` (target-count-limited, FAST-mode `max_delay_ipc=5`), `fraction_of_ceiling=0.695`, **not contaminated**. FULL mode's larger `max_delay_ipc=12` will push this ceiling further away and should be re-checked.

## 7. Feature-budget audit

At the Part 5 reference point (protected_integrable, g=0.5, J=0.33):

| group | n_features | numerical rank | effective rank | M | NL_instant | NL_temporal |
|---|---|---|---|---|---|---|
| X_M | 3 | 3 | 1.7 | 1.927 | 0.000 | 0.192 |
| X_P | 375 | 139 | 4.3 | 5.804 | 0.000 | 2.424 |
| X_M+X_P | 378 | 139 | 4.0 | 5.812 | 0.000 | 2.431 |
| X_M+X_P+cross | 382 | 139 | 4.0 | 5.814 | 0.000 | 2.423 |

Random-projection budget scan of `X_P` alone (n_repeats=3, FAST mode): budget 3 -> M=2.13+-0.48; budget 8 -> M=3.53+-0.34; budget 16 -> M=4.72+-0.36. Even at a feature budget matched to `X_M`'s raw dimension (3), the processor alone already reaches M=2.13, above `X_M`'s own M=1.927 — the processor's memory-like capacity is not merely an artifact of having 125x more features.

Leakage-safe residualization (`X_P_perp = (I - P_XM) X_P`, projection fit on train only): `M(X_P_perp)=4.122` (down from `M(X_P)=5.804`, a ~29% drop) while `NL_instant(X_P_perp)=0.023` stays near zero. Interpretation: a meaningful fraction of the processor's raw memory-like capacity is redundant with what `X_M` already encodes, but a large non-redundant M-like component remains in the processor even after removing everything linearly predictable from the memory register — the processor is not merely re-exposing the memory's own information.

## 8. Seed and statistical design

FAST mode used **1 reservoir seed** for the discovery grid, response-surface, reset ablation, and timescale/back-action measurements (nested-seed generation via `make_nested_seeds` demonstrated for 2 reservoir indices, `tests/test_validation_utils.py` 11/11 passing, but only reservoir_idx=0 was used for actual physics runs this pass). This is explicitly insufficient for Gates H/I and for any seed-robustness or neighborhood-robustness claim — FULL mode requires >=5 reservoir seeds x >=3 input seeds.

## 9. Chaos/EOC diagnostics

Two independent diagnostics (`<r>` level-spacing ratio, operator entanglement) computed via `processor.processor_chaos_diagnostics` at all 9 discovery-grid points (Figure 05). **Limitation, stated explicitly**: exact symmetry sectors of the processor Hamiltonian are not resolved before computing `<r>` — a known simplification carried over from every prior pass in this project, not newly introduced here.

## 10. Local response methodology

FAST mode used a single 2-point central difference per axis (`H_m=0.1`, `H_g=0.05`, `H_J=0.05` in raw units) at the discovery grid's best-`NL_instant` point (`g=0.325, J=0.600, m=0.5`). This is a **reduced** version of Part 10's full 3-step-size / 5-point-stencil design; `fit_response_surface` and `stencil_offsets_5point` in `decoupled_qrc/validation_utils.py` implement the full FULL-mode design and are unit-tested (`tests/test_validation_utils.py`, exact recovery of known linear/quadratic analytic toy functions), but were not exercised on live circuit data this pass. **Derivative stability (Gate B) cannot be assessed from a single step size and is not claimed.**

## 11. Reset ablation

`K in {1, 4, None}` (FULL mode would add `K=2`), implemented as `qc.reset()` on all processor qubits every `K` steps — a valid CPTP channel, verified by `tests/test_reset_ablation.py` (trace-1/Hermitian/PSD state, exact reproduction of the persistent architecture at `K=None`, exact `|0><0|` processor state at `K=1`). Results at the single candidate point: `K=1: M=1.379, NL_instant=0.013`; `K=4: M=1.660, NL_instant=0.061`; `K=None: M=5.531, NL_instant=0.045`. Frequent reset collapses the processor's memory-like capacity as expected (a genuine information-theoretic sanity check that the processor's `M` really does depend on retained state), but does **not** increase `NL_instant` — if anything `K=4`'s `NL_instant=0.061` is the largest value seen, but this is a single, noisy point, not a trend established across seeds.

## 14. Scope limitations

- 1 reservoir seed, 1 input seed (FAST mode) — no seed-robustness evidence.
- 3x3 discovery grid — coarse; a genuinely decoupled region could exist between grid points or outside the scanned range.
- Single step size for all derivatives — no derivative-stability evidence (Gate B).
- No held-out confirmation (Part 15) — the "best" point was selected and evaluated using the *same* run, i.e. this is a discovery-stage number, not a confirmed one; even if it had passed the gates, that would not by itself be a validated claim without independent confirmation data.
- No neighborhood robustness sweep (Gate I).
- `tau_M` fit failed to converge at the one point checked (r2=nan) — timescale-based reasoning is not usable from this pass.
- Symmetry sectors not resolved in the chaos diagnostics (long-standing project limitation, not new).

## 15. Decision and recommended next experiment

**Outcome selected: E — inconclusive at the confirmatory level (FULL mode was not run), combined with an unfavorable FAST-mode exploratory signal.**

Formally, none of outcomes A/B/C/D can be asserted because the required FULL-mode evidence (>=5 seeds, held-out confirmation, neighborhood sweep, multi-step-size derivatives) does not exist. What can be said is: in this single-seed, coarse-grid, single-step-size exploratory pass, **no candidate point showed anything resembling directional decoupling** — the best-`NL_instant` point in the grid had an `R_NL_instant` below 1 and a response angle near 0 degrees (M and NL_instant move together, not orthogonally). This is a *preliminary* signal, not a confirmed one, but it points away from Outcome A (robust decoupling) and does not obviously support investing directly in a FULL-mode confirmation run of *this exact 3x3 grid's* candidate point.

**Recommended next experiment** (not implemented in this notebook, per the rules): before spending FULL-mode budget on held-out confirmation of a weak candidate, run a **wider and finer FAST-mode discovery scan** (larger grid or Sobol/LHS sampling across the full `(m,g,J)` cube, still 1 seed, still cheap) specifically to check whether *any* region shows `R_NL_instant` trending above 1 before committing to the expensive 5-seed x 3-input-seed FULL-mode confirmation design. If a wider scan also fails to find any promising region, that constitutes real evidence toward Outcome D (no robust region survives) and motivates investigating Krylov-sectorized memory as the next architectural direction — but that investigation is out of scope for this notebook.
