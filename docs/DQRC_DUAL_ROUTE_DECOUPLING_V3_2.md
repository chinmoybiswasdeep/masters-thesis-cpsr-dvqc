### 1.2 Causal diagnosis

V3's processor put the input **inside the Hamiltonian exponent**
(`nonlinear_processor.py:98` — `U_P = exp(-i(H_0(g,J) + Σ_k d_k V_k)·dt)^R` acting on a reset
`|0…0>`). Every feature is then a trigonometric function of `u` *regardless of* `(g,J)`, so `NL_0`
was already near its maximum before the controls acted — hence an encoder fraction above one
(`0.7201 / 0.6632 ≈ 1.09`) and a dynamic range of `E_NL = 0.074` against a 0.20 gate.

Independently, ranking memory by maximum `M` put `m* = 0.95` on the exact upper boundary of its own
range, where the delay profile is ceiling-saturated and no symmetric five-point stencil fits — which
is why the derivative was unstable.

Both are design faults. V3.1's statistics were then asked to resolve a signal the architecture had
already destroyed.

### 1.3 On the identical ablations (concern 7)

V3.2 establishes that a *legitimate* mechanism for identical ablation features exists and is
provable: a Z-diagonal unitary acting on the Z-diagonal encoder ensemble `ρ(u)^{⊗N}` is the identity
channel **on that ensemble**. Measured here: `‖ΔU‖_F` up to 4.14 with `‖ΔFeatures‖ ≈ 2e-15`. So
`encoder_only`, `two_body_only` and `four_body_only` *must* coincide in features while differing in
Hamiltonian and unitary.

That symmetry does **not** explain V3.1's pairing of `full` with `two_body_only`, so V3.1's
duplicates remain a live aliasing suspicion. V3.2's `ablation_distinctness` therefore reports
Hamiltonian, unitary, state and feature differences **separately**, and flags any feature-identical
pair outside the provable set as an unexplained defect that blocks discovery.

## 2. The two architectural corrections

### 2.1 An encoder that is linear at the observable level

`ρ(u) = (I + sZ)/2` per qubit with `s = 2u − 1`, and `ρ_P(u) = ρ(u)^{⊗N_P}`. Two properties are
**exact**, verified by Gauss-Legendre quadrature rather than by sampling
(`tests/test_v3_2_encoder.py`, `tests/test_v3_2_processor.py`):

1. Under any product of single-qubit channels — which is what the processor *is* at `g = J = 0` —
   every **local** Pauli expectation is exactly affine in `s`. Affine-fit residual `5.6e-16`; centred
   feature rank 1. Therefore **`NL_0(g=0, J=0) = 0` exactly for the preregistered local readout**, and
   `f_enc = 0` follows by construction rather than by tuning.

   **This is a property of the readout, not of the encoder, and an earlier draft of this document
   overstated it as physics.** The encoder state `ρ(u)^{⊗N_P}` manifestly carries correlations of
   every degree up to `N_P`; the *local* readout is simply blind to them until the interaction
   rotates them onto single-site axes. Measured at `g = J = 0`, N_P=4, same encoder, varying only
   the observable set:

   | readout set | `NL_0` at g=J=0 |
   |---|---|
   | local `{X,Y,Z}_i` (preregistered) | `0.0000` |
   | local + two-body `Z_iZ_j` | **`1.0000`** (C₂ = 1.0) |
   | local + `Z_iZ_j` + `Z_iZ_jZ_k` | **`2.0000`** (C₂ = C₃ = 1.0) |

   So the correct statement is: *with the preregistered local readout, all measurable instantaneous
   nonlinearity is interaction-generated.* The claim is contingent on the readout, which is why the
   readout is preregistered, fixed across every control setting, and counted as a resource.
2. `ρ_P(u)` is multilinear across the `N_P` copies, so every feature is a polynomial in `s` of degree
   at most `N_P`. Capacity above degree `N_P` is measured at `~1e-17`. This is a **structural** zero
   and is reported as such — never as an empirically absent capacity. It also makes the input-copy
   count a physical resource, counted in every resource row.

The same encoder was already used by the V3 memory bank (`memory_bank.encode_diagonal_z`), so both
modules now share one input convention.

### 2.2 Memory selected by slope stability, not by capacity

Candidates must pass hard filters (interior stencil margin ≥ 2h, no ceiling contamination, null
fraction below limit, adequate samples, cross-seed sign-consistent local slope) *before* any ranking,
and are then ranked by

```
1.0·z(|∂M_long/∂m̃| / se) + 0.8·z(interior margin) + 0.3·z(M_long) − 0.5·z(null bias)
```

Capacity is a minor term by design. `stencil_points` **raises** rather than silently one-siding a
stencil that would leave the domain, so a boundary candidate like V3.1's `m* = 0.95` cannot be
selected at all.

### 2.3 The processor Hamiltonian, verified rather than assumed

`H_P(g,J) = H_mix + g·H_2 + J·H_4` with `H_mix = Σ_i (Ω_{x,i}X_i + Ω_{y,i}Y_i + h_i Z_i)` (site
disorder from the disorder seed), `H_2 = Σ_⟨i,j⟩ Z_iZ_j` (chain), `H_4 = Σ_{|q|=4} Z_aZ_bZ_cZ_d`.
Layered as `U = A·∏_r[B(g,J)·A]`.

Checked, not assumed:

- Hermiticity exact (`0.0e+00`); `[H_2, H_4] = 0` exactly (both Z-diagonal); `[H_mix, H_2] = 6.67`
  and `[H_mix, H_4] = 13.34` at N_P=5 — the required noncommutation is present.
- **Layer ordering is not cosmetic.** Both interaction terms are Z-diagonal and the encoder state is
  Z-diagonal, so an interaction-first ordering makes the first `B` layer an exact no-op. Mixing must
  come first, with a final mixing layer to rotate the generated correlations onto locally measurable
  axes.
- **Site disorder is required, not decorative.** Without it the chain's reflection symmetry makes
  sites pairwise equivalent and collapses the feature rank. Every disorder term is single-qubit, so
  it cannot generate nonlinearity and `NL_0(0,0) = 0` is preserved exactly.
- **N_P = 5 rather than 4.** At `N_P = 4`, `H_4` is a single term whose locally observable nonlinear
  contribution is negligible (nonlinear fraction 0.0012) — `J` would not be independently
  identifiable. At `N_P = 5` there are `C(5,4) = 5` quartets and `mix+four-body` alone reaches
  `C_2..C_5 = 1.0`.

## 3. A structural fact about the primary metric

**In the noiseless *and infinite-data* limit, instantaneous capacity is exactly degenerate.** Once
the features span polynomials of degree ≤ `N_P`, the exact quadrature capacity `C_d` equals **1.000**
for every `d ≤ N_P`. Measured at N_P=5 by Gauss-Legendre quadrature: `NL_0` steps from `0.003` to
`1.645` between `(g,J) = (0,0)` and `(0.1,0.1)` and is then flat out to `(1.3,1.3)`. In that limit
the metric is pinned at its ceiling and has no derivative at all.

**A correction to an earlier statement of mine.** I initially generalised that to "the metric has no
dynamic range without shot noise". The measured sensitivity analysis (§7.4,
`results/dqrc_dual_route_v3_2/shot_budget_sensitivity.json`) shows that is too strong: with *finite*
data (T = 1200) the finite sample size is itself a regulariser, and even with noiseless features
`E_NL = 0.222` — above the 0.20 gate, though with the median sitting at 82% of the target-count
ceiling where the metric is compressed and close to the 0.95 contamination flag.

So the finite shot budget is justified on two accurate grounds rather than one overstated one: it
moves the metric away from its ceiling (median 37–60% of ceiling instead of 82%), and it gives the
capacity a *physical* noise reference rather than an incidental one set by the sample size. It is
selected during CALIBRATION and matched as a resource across every architecture and baseline.

The degree bound itself is *not* readout-contingent in the same way: it follows from `ρ_P(u)` being a
product of `N_P` factors each affine in `s`. An independent check with a non-diagonal but still
`s`-affine product encoder `(I + sX)/2` reproduces the bound (degrees > `N_P` at ~1e-26), and a
non-product encoder breaks it (degrees 6, 8 reaching 0.54, 0.58) — so the bound comes from
*productness*, not from diagonality.

The shot model is analytic (exact expectation plus Gaussian noise of variance `(1−p²)/S` from a
dedicated `shot_noise` seed stream) and is **validated against true binomial sampling**, not assumed
(`tests/test_v3_2_readout.py`). Measurement settings are counted honestly: `X_i, Y_i, Z_i` do not
commute, so the local readout costs 3 settings × S shots per timestep, and that is the number entered
into the resource table.

Memory is *not* shot-limited the same way: `M_long` measured 4.648 noiseless versus 4.588 at 10k
shots. Linear memory has genuine dynamic range without a noise reference because there are many
delays and only rank-limited features. This asymmetry is reported, not smoothed over.

## 4. A planning assumption that measurement refuted

The approved plan asserted that in the directional architecture the memory-row off-diagonals
`∂M_long/∂g̃` and `∂M_long/∂J̃` would be **structurally zero**, because the processor is re-prepared
fresh each step and discarded, so it never couples back into the memory.

**That is wrong, and direct measurement refuted it.** `U_MP` is a *joint* unitary, so tracing the
processor away leaves the memory in a state that depends on what the processor was in — hence on
`(g, J)`. Measured at the **production configuration** `N_M = 4`, `N_P = 5`, `λ = 0.35`:

| quantity | N_M=4, N_P=5 (production) | N_M=N_P=3 |
|---|---|---|
| `max\|∂X_P/∂m\|` | `3.9e-02` | `5.6e-02` |
| `max\|∂X_M/∂g\|` | `8.8e-04` | `4.4e-03` |
| `max\|∂X_M/∂J\|` | `6.6e-03` | **`0.0` — structurally zero** |

**Correction:** an earlier draft of this document attributed these numbers to `N_M = N_P = 3`. They
are the production figures. The distinction matters: at `N_P = 3` there are `C(3,4) = 0` quartets, so
`‖H_4‖ = 0` and `J` has no effect at all — the `∂X_M/∂J` entry is structurally zero there and cannot
evidence anything. The substantive claim holds at the production size, where all three are far above
the `1e-10` isolation tolerance. This is the same physical back-action Gate L bounds.
Consequence: **all six Jacobian entries are empirical at λ > 0**, and Gate F applies to all three
off-diagonals rather than to `∂NL_0/∂m̃` alone — a stronger test than the plan anticipated. At
`λ = 0` every one of them returns to exactly zero, which is what Gate A certifies.
`tests/test_v3_2_architecture.py::test_tracing_out_the_processor_leaves_g_J_dependent_back_action_on_memory`
pins this so the refuted assumption cannot quietly return.

## 5. Process guards, each tied to a V3.1 defect

### 5.1 SMOKE cannot freeze and cannot claim
`StageMachine.freeze` raises unless the stage is DISCOVERY, calibration passed, and every declared
hard gate passed. `assert_claim_allowed` caps SMOKE and CALIBRATION at claim level 0 and DISCOVERY at
1. V3.1 froze from SMOKE with its processor gate failing, and printed "claim level 3" from a run
whose confirmation never executed.

### 5.2 Calibration failure blocks discovery
The `CALIBRATION → DISCOVERY` transition raises `CalibrationNotPassed` unless a passing calibration
was recorded.

### 5.3 Confirmation loads, never recreates
`load_frozen_discovery` verifies the artifact's own sha256 and returns a plain dict; a tampered
artifact raises, and `assert_confirmation_matches_frozen` rejects a payload that drifted from the
freeze. `confirmation_complete` is **derived** from an expected-row-count check (every expected row
present, no duplicates, no unexpected rows, every row carrying the frozen config hash, every required
metric finite) and is never assigned.

### 5.4 A disjointness proof over an empty set now fails
`assert_seeds_disjoint_nonempty` requires both sets to be non-empty and checks all eight seed streams.
The V1–V3.1 helpers are deliberately **not modified** — this repository is append-only and their
behaviour must stay reproducible — so their vacuous pass is pinned as a regression test
(`test_legacy_disjointness_proof_passes_vacuously_on_an_empty_set`) beside the strict V3.2 behaviour.
*This is a deviation from the approved plan, which proposed editing `v3_seeds.assert_disjoint`; not
editing it is safer and more consistent with the repository's own discipline.*

### 5.5 A cache key that cannot alias — designed and tested, but NOT exercised
New namespace, `CACHE_SCHEMA_VERSION = "v3.2.0"`, with the fields V3's key lacked: the Hamiltonian
term list, encoder id, observable set, `Δt`, `R`, layer ordering and ablation name.
`tests/test_v3_2_cache.py` includes an intentional-alias test constructing the collision the real key
must avoid.

**Caveat, found in review:** outside its own tests, only `environment_fingerprint` is actually called
by the pipeline. The key builders and the `cached_v3_2` decorator have **no call sites**, so V3.2 as
executed performs no result caching and Gate B's `cache_equivalence` is always `None` (skipped). An
earlier draft of this section also claimed the key carries the shot budget and shot seed; the
builders do not include them (callers would have to pass them as extra fields). See §8b.10.

## 6. Statistical corrections

- **Sample size** `n_train ≥ max(10·r_eff, 500)` is checked and reported, not assumed. V3.1 ran on
  `n_train = 43` with a null fraction near 0.50; that combination is now a hard validity failure.
- **Nulls**: 99 repetitions in discovery settings, 199 in confirmation settings, drawn from the
  `null_surrogate` stream.
- **Four numbers always**: raw, null, bias-corrected `max(raw − null, 0)`, and the **unchanged
  legacy** `capacity` (`raw if significant else 0`), so V3.1 comparisons stay valid and no legacy
  metric is silently redefined.
- **Classification** reuses `ipc_decomposition.py:114` unchanged: instantaneous means
  `degree ≥ 2 AND delays == (0,)`, so a cross-delay target with a τ=0 factor is never counted as
  instantaneous.
- **Adaptive delays** grow until the linear-memory tail sits below the null band for three
  consecutive delays, or a documented resource cap is hit — recorded as `reason="resource_cap"` so a
  truncated tail is never mistaken for a decayed one.
- **Speed without redefinition**: `RidgeBank` factorises the standardised training design once by SVD
  and reuses it for every target, surrogate and alpha (≈49× faster than refitting). It reproduces the
  repository's own `ipc._capacity_score` to **4.3e-17 on the toy fixture** and, on the rank-deficient
  production design, to **9.6e-12** — inside the 1e-10 test tolerance, with the alpha search,
  standardisation, clipping and surrogate paths all covered. Ridge is solved via SVD; there is no explicit matrix
  inverse anywhere.

|---|---|---|

The encoder-fraction result is solid: **for the preregistered local readout the encoder contributes

**The `E_NL` pass was initially grid-dependent, and the shot-budget repair fixed it.** Independent

| grid subset | n | `E_NL` at S=1000 (defective rule) | `E_NL` at S=100 000 (corrected) |
|---|---|---|---|

At the noisiest budget the spread came substantially from the `g = 0` row and `J = 0` column — the
same structural zero that prerequisite P2 independently certifies — so P2 and P5 were not independent
tests and the pass sat one grid-inclusion decision from a failure. **At the corrected budget the
interior alone clears the gate**, so the dynamic range is now carried by genuine `(g,J)` modulation
rather than by the axes. This was not achieved by retuning: the shot rule had an unreachable
saturation branch (§8b.8), and fixing that defect changed which budget the preregistered rule
selects. Both numbers are reported so the reader can see the difference the repair made.

| mechanism | selected m* | slope `∂M_long/∂m̃` | SNR | interior margin | `M_long` | valid | inside its stable window? |
|---|---|---|---|---|---|---|---|
| fractional_swap | 0.550 | **−3.09** | 6.4 | 0.444 | 3.581 | 6 of 11 | **no** — window is [0.15, 0.40], slope +11.8 |
| leaky_collision | 0.500 | **+7.13** | 17.2 | 0.500 | 2.440 | 8 of 11 | **yes** — window [0.15, 0.85], slope +6.3 |

cannot be selected at all.

**leaky_collision is the better-behaved mechanism on this evidence** — positive slope, nearly three
times the SNR, the largest interior margin, more valid points, and a selected point that sits inside
its own stable window. The pipeline nonetheless reports `selected_mechanism = fractional_swap`, purely
because it is first in the list (§8.2). Both are carried forward.

### 7.4 Shot-budget sensitivity — the dynamic range is not an artifact of S

The adversarial question is whether choosing `S` during calibration manufactures the dynamic range.
It does not. Re-measuring the whole 6×6 `(g,J)` surface at four budgets (2 reservoir seeds):

| shots | `E_NL` | median `NL_0` | median / ceiling |
|---|---|---|---|
| 1 000 | 0.414 | 1.468 | 0.37 |
| 10 000 | 0.528 | 1.897 | 0.47 |
| 100 000 | 0.653 | 2.413 | 0.60 |
| noiseless | 0.222 | 3.292 | 0.82 |

**Gate E's dynamic range passes at every budget tested, including the noiseless one.** `E_NL` is not
monotone in `S`: it rises with shots and then collapses toward the ceiling when noise is removed
entirely, exactly as the ceiling argument predicts. The finding is robust to which budget the rule
selects — which is why repairing the shot rule (§8b.8) changed the selected budget from 1 000 to
100 000 without putting the Gate E verdict at risk. It did, however, strengthen the *interior*
margin substantially (§7.2).

## 8. Known weaknesses of this iteration

These are stated because they are real, not because they changed the outcome. **None of them was
fixed after seeing the results** — doing so would be the post-hoc tuning this iteration exists to
prevent. They are specification defects to repair *before* discovery runs.

1. **The memory ranking still selects a descending-branch point for fractional_swap.** In the
   corrected run `m* = 0.550` has a *negative* slope (−3.09) and lies outside that mechanism's longest
   sign-consistent window `m ∈ [0.15, 0.40]`, where the slope is +11.8. Gate D requires a stable
   *nonzero* slope, not a positive one, so the point is admissible — but the weighting
   (`0.8·z(margin) + 0.3·z(M_long)`) favours the flatter, higher-capacity side of the maximum. The
   preregistered rule should have included "prefer the longest sign-consistent window". Figure 03
   shows this directly. Note leaky_collision does **not** have this problem: its selected point is
   inside its window with a positive slope.
2. **Mechanism selection fell through to list order, and it picked the worse-behaved mechanism.**
   Both passed; `selected_mechanism` takes `passing[0]`, which is `fractional_swap` only because it is
   first in the list. There was no preregistered tiebreak. On every stability measure that matters
   — slope sign, SNR (17.2 vs 6.4), interior margin, valid-point count, and whether the selected point
   lies inside its own stable window — `leaky_collision` is the better candidate. **Both are therefore
   carried forward** rather than one being silently adopted, and a preregistered tiebreak must be
   added before discovery.
3. **The processor operating point was chosen by maximum capacity** among interior grid points —
   the very criterion this iteration rejects for memory. It affects only *where* `ΔNL_interaction`
   was measured (a difference, not a derivative), so no derivative claim is contaminated; but before
   discovery the processor point must be re-selected on a mid-slope of the `(g,J)` surface.
4. **The shot ladder never saturated**, so "first non-saturated budget" degenerated to "smallest
   budget". §7.4 shows the conclusion survives this, but the rule is poorly specified.
5. Calibration used 3 reservoir × 2 input seeds. That is a prerequisite check, not a confirmatory
   result, and it is not a substitute for the 5 × 3 design confirmation would require. Note also that
   `v3_seeds.make_seeds` derives the `disorder` stream from **both** `reservoir_idx` and `input_idx`,
   so "3 reservoir × 2 input" is really 6 independent disorder realisations — the hierarchical
   bootstrap's between/within decomposition is mislabelled for this design.

### 8b. Found by independent adversarial review, after the results existed

An independent reviewer that took no part in the design audited the implementation and the claims.
It found four defects that I **reproduced by execution** and have now fixed and pinned with tests,
plus weaknesses that are reported rather than fixed. This section exists because the review changed
what this document can honestly claim.

6. **The primary architecture fails its own back-action gate at its default coupling.**
   `ArchitectureSpec.lam = 0.35`; Gate L's threshold is 0.05. Measured at the calibration operating
   point (`m=0.65`, `g=0.2`, `J=0.6`, N_M=4, N_P=5):

   | λ | max observable disturbance | max trace distance | Gate L |
   |---|---|---|---|
   | 0.10 | 0.0132 | 0.0117 | PASS |
   | 0.20 | 0.0290 | 0.0287 | PASS |
   | 0.30 | 0.0494 | 0.0532 | FAIL |
   | **0.35 (default)** | **0.0655** | **0.0684** | **FAIL** |

   The default has **not** been lowered to make the gate pass — that would be exactly the post-hoc
   tuning this iteration exists to prevent. λ must be selected during calibration subject to Gate L
   before discovery; this measurement says λ ≤ 0.2 at this operating point.

7. **The ceiling-contamination guard was unreachable.** Gate C and the memory filter read a dict key
   (`frac`) that `ceiling_audit` does not emit (it emits `fraction_of_ceiling` and
   `ceiling_contaminated`). The lookup returned `None`, and `None` passed every comparison — so the
   guard against the *exact* defect V3.1 was diagnosed with was inert, and its test passed only
   because it hand-built the wrong key. **Fixed**: both call sites read the real keys, a missing
   fraction is now refused rather than treated as safe, and the test fixture is built from
   `audit_ceiling(...)` itself. No reported number changes (max observed fraction was 0.477).

8. **The shot-budget selection was a no-op with a dead failure branch.** Saturation was tested on the
   *bias-corrected* `NL_0` against `0.97 × ceiling`; since `NL_0 = raw − null` and `raw ≤ ceiling`,
   that condition is unreachable at any budget. The ladder therefore always returned its first entry,
   so "first unsaturated" silently meant "noisiest", and it was probed from a **single** seed bundle
   against this project's own rule. **Fixed**: saturation is tested on the raw capacity, probed across
   every bundle, and the rule now prefers the *largest* unsaturated budget. Calibration was re-run
   under the corrected rule: the selected budget moved 1 000 → 100 000, `E_NL` 0.4343 → 0.6089,
   `f_enc` 0.0034 → 0.00079, and ΔNL_interaction 1.888 → 2.538 (CI [2.341, 2.724]). Most importantly
   the interior-only `E_NL` moved 0.1968 → 0.2907, turning a latent failure into a pass (§7.2). Both
   runs are reported.

9. **Two stage guards were bypassable in four lines.** `record_calibration(report, passed=True)`
   accepted the caller's verdict without inspecting the report; `freeze(gates_passed=None)` treated
   "no gates supplied" as "no gate failed"; a machine could be constructed directly at any stage; and
   `SMOKE → REPORT` granted claim level 5 because `MAX_CLAIM_LEVEL[REPORT]` was a constant. All four
   reproduce V3.1 failure modes, and I verified each by executing the bypass. **Fixed and pinned**:
   the calibration verdict is derived from the report, `freeze` requires explicit gate verdicts,
   construction is restricted to SMOKE, and the claim cap is derived from the stages actually
   completed.

10. **`v3_2_cache.py` is not wired into the pipeline.** Only `environment_fingerprint` is called; the
    key builders and the `cached_v3_2` decorator have no call sites outside their own tests. §5.5
    described a key the running code does not use, and Gate B's `cache_equivalence` is consequently
    always `None` (skipped). **V3.2 as executed performs no result caching** — acceptable at this
    scale (calibration is ~9 minutes), but the cache-aliasing protection is designed and tested,
    not exercised.

11. **The `randomized` negative control is never evaluated over the `(g,J)` grid**, despite the
    module docstring saying that a metric which responds to `(g,J)` there is measuring a bug. Its
    test is tautological — the `randomized` branch returns before reading `g` or `J`. Relatedly, in
    the *noiseless* diagnostic `randomized` reaches `NL_0_exact = 4.0` exactly like `full`, so
    §2.3's "J is independently identifiable at N_P=5" is **not** evidenced by that diagnostic: a
    random unitary reaches the same ceiling.

12. **Selection-then-test in P3.** The operating point is the argmax of `NL_0` over the same 36
    points from which the paired CI is then computed, with no selective-inference correction
    (winner's curse). The verdict survives here only because the effect is large (Δ ≈ 1.89 against a
    null of 0.007); the mechanism would not survive a tight call.

13. **The memory-slope error bars overstate their precision.** `slope_se` pools 12 finite differences
    from two adjacent intervals as i.i.d. replicates of a single slope, roughly halving the true
    standard error — and `slope_snr` carries the largest weight in the ranking. With 3 outer clusters
    the percentile CI behind every `ci.lo > 0` verdict is also under-covered.

14. **The surrogate null is asymmetric.** `profile_capacities` permutes only `y[train]`, then selects
    the ridge alpha against the *unpermuted* `y[val]`, so the null gets information it should not
    have. Direction of the bias: the null is shrunk, making bias-corrected capacity slightly
    optimistic.

15. **Minor.** The quoted `RidgeBank` equivalence of `4.3e-17` is the toy-fixture best case; on the
    rank-deficient production design the worst deviation is `9.6e-12` (still inside the 1e-10 test
    tolerance, with the alpha search, standardisation, clipping and null paths all covered).
    `add_shot_noise` is unclipped Gaussian, so estimates can fall outside `[-1, 1]` unlike the
    binomial estimator it is validated against. The `n_train >= max(10*r_eff, 500)` rule never binds
    on rank here (`r_eff` approximately 1.5), so it reduces to the absolute floor.

## 9. Claim level and decision outcome

**Highest supported claim level: Level 1 — structural route isolation, with falsifiable controls,
and only for the λ = 0 control architecture.**

Level 1 is *not* memory–nonlinearity separation and is not described as such here. It rests on Gate A:
`max|∂X_P/∂m| = 0.0` exactly at λ = 0, with an injected-dependency control that fails as required, plus
a fully passing test suite. Level 2 would require both modules to show independent diagonal functional
control under held-out confirmation; calibration established the *prerequisites* for that on
discovery-family seeds only, which is explicitly not confirmatory evidence. The stage machine now
enforces the cap structurally: it is derived from the stages actually completed, so a SMOKE-only run
cannot reach any claim level above 0 by any route (§8b.9).

**An important scope limit, added after independent review.** The *primary* architecture (λ = 0.35)
currently **fails Gate L**, its own back-action bound (§8b.6). So even the Level 1 claim is
established for the structurally isolated λ = 0 control architecture, while the primary architecture
that Gate F would need remains **unusable at its documented coupling** until λ is calibrated subject
to Gate L. That is a prerequisite failure for the primary architecture, and it is one of the reasons
discovery must not be run in this state.

**Decision outcome: none of A–F is selected yet.** The preregistered outcomes A–F all describe the
state *after* a completed held-out confirmation. This iteration terminated earlier, by design and not
by failure:

- Outcome **B** does **not** apply — it is for structural isolation *with inadequate diagonal
  control*, and both diagonal controls passed their prerequisites.
- Outcome **D** does **not** apply — the IPC statistics are valid (null fractions 0.03–0.08 against a
  0.20 limit, `n_train = 644` against a required 500, no unexplained ablation aliasing).
- Outcome **A**, **C** and **E** are unreachable without confirmation data.

The honest statement is: **calibration succeeded on its own terms, discovery has not been run, and no
separation claim is made.** The architectural repair to the encoder is demonstrated and is the real
result of this iteration. Independent review showed the first calibration verdict rested on weaker
foundations than its raw PASS suggested — the shot budget was selected by an unreachable test
(§8b.8), the ceiling guard was inert (§8b.7), two stage guards were bypassable (§8b.9), and the
`E_NL` margin was carried by the structurally-zero axes (§7.2). Those are now fixed, and the re-run
under the corrected rules is *stronger*, not weaker: the interior-only dynamic range went from a
latent failure to a pass. The one finding that remains open is that the primary architecture fails
its own back-action gate at its documented coupling (§8b.6), which is reported rather than tuned
away. The scientific question the study was built to answer remains open, and
this document does not narrow it.

## 11. Recommended next experiment
